# Видео по ID для Lampa

Плагин открывает видео по `content-id` видеоплеера. В боковом меню Lampa появляется пункт **Видео по ID**. Экран поддерживает выбор сезона, серии, озвучки и качества. Если источник возвращает одиночное видео в том же формате, экран показывает сразу озвучку, качество и воспроизведение.

## Опубликовать JavaScript на GitHub Pages

1. Распакуйте архив. Откройте каталог `lampa-content-id`, в котором лежит этот README.
2. Создайте пустой репозиторий GitHub. Для публикации через GitHub Free используйте публичный репозиторий. Загрузите содержимое каталога в корень репозитория, включая `docs/lampa-content-id.js` и `docs/.nojekyll`. Это можно сделать через Git из распакованного каталога. Замените `USER` и `REPO` своими значениями.

   ```bash
   git init -b main
   git add .
   git commit -m "Add Lampa content-id plugin"
   git remote add origin https://github.com/USER/REPO.git
   git push -u origin main
   ```

3. В настройках репозитория откройте **Settings → Pages**. В **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/docs`. Нажмите **Save**.
4. После публикации проверьте прямой HTTPS-адрес JavaScript. В ответе должен открываться файл, который начинается с комментария `Видео по ID`.

   ```text
   https://USER.github.io/REPO/lampa-content-id.js
   ```

   Это шаблон адреса сайта проекта на стандартном домене. Если у репозитория настроен другой адрес, возьмите базовый HTTPS-адрес из **Settings → Pages** и добавьте `/lampa-content-id.js`.

Документация GitHub по [публикации из ветки](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [типам сайтов и доступности Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) и [HTTPS](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https).

## Установить и открыть

| Устройство | Действия |
| --- | --- |
| Ноутбук | В Lampa откройте **Настройки → Расширения → Добавить плагин**. Вставьте HTTPS-адрес файла, подтвердите установку и откройте **Видео по ID** в боковом меню. На экране плагина работают мышь, стрелки и Enter. |
| Smart TV | В сборке Lampa с поддержкой внешних расширений откройте те же настройки. Введите HTTPS-адрес экранной клавиатурой и подтвердите установку. В боковом меню найдите **Видео по ID**. Используйте стрелки, OK и «Назад». |

Названия соответствуют русскому интерфейсу проверенной сборки Lampa. После установки пункт меню появляется при загрузке скрипта. Если меню уже открыто, выйдите из него и откройте снова. Наличие кнопки **Добавить плагин** зависит от сборки Lampa. [Строки русского интерфейса и экран добавления в исходниках Lampa](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/lang/ru.js).

1. Выберите **ID видеоплеера** и введите цифры. Для проверенного сериала «Против всех» введите `144537`. В экранной клавиатуре Lampa клавиша подтверждения и кнопка «Назад» возвращают на экран с введённым ID.
2. Нажмите **Загрузить**. Выберите сезон, серию и озвучку. Варианты озвучки берутся из ответа для конкретной серии. Для `144537` проверенный ответ содержал только «Оригинал».
3. Для плейлиста с известными разрешениями выберите **Авто** или одно из показанных значений. Нажмите **Воспроизвести**.
4. Закройте плеер кнопкой «Назад». Фокус вернётся к **Воспроизвести**. Кнопки **Предыдущая серия** и **Следующая серия** на экране плагина меняют выбранную серию, в том числе на границе сезонов. Нажмите **Воспроизвести**, чтобы запустить новую серию.

Плагин запоминает последний подтверждённый ID, выбранный сезон и серию для загруженного ID, а также предпочтения по качеству и озвучке в локальном хранилище устройства. При повторном открытии список загружается для сохранённого ID. Если предпочтительный вариант появляется в другой серии, плагин снова предлагает его.

## Как выбирается поток

- Плагин загружает каталог методом GET по проверенному маршруту `/balancer-api/proxy/playlists/catalog-api/episodes?content-id=…`. Перед каждым воспроизведением он повторно запрашивает каталог и определяет текущую ссылку выбранной серии и озвучки. В хранилище записываются только настройки и идентификаторы.
- Для `.m3u8` плагин читает `#EXT-X-STREAM-INF` и берёт высоту из `RESOLUTION`. Относительные ссылки разрешаются от конечного адреса ответа после перенаправления. В режиме **Авто** выбирается наибольшая указанная высота. Из двух записей одной высоты выбирается запись с большим объявленным средним битрейтом или, если средний отсутствует, по `BANDWIDTH`. [RFC 8216, раздел 4.3.4.2](https://www.rfc-editor.org/rfc/rfc8216.html#section-4.3.4.2).
- У прямого MP4 и у медиа-плейлиста с неизвестным разрешением отображается тип источника. Для master-плейлиста с отдельной аудио- или видеодорожкой плеер получает master, чтобы сохранить связь дорожек. Если прочитать HLS не удаётся, экран показывает причину и предлагает открыть исходную ссылку в плеере.
- Если выбранное разрешение исчезло с момента предварительной проверки, экран сообщит об этом и покажет актуальный выбор. Можно сменить настройку или повторить запуск с обновлёнными данными.

Используйте материалы и источник, к которым у вас есть разрешённый доступ. Наличие рекламы в потоке остаётся неизвестным при `hasAdv: null`. Плагин выполняет запросы к каталогу и плейлистам, а воспроизведение передаёт штатному плееру Lampa.

## Проверки и ограничения

| Область | Что проверено |
| --- | --- |
| Живой каталог | 6 ноября 2026 года `144537` вернул 46 серий. По сезонам это 13 + 13 + 20. По расширению `filepath` — 45 HLS и один MP4, сезон 2, серия 7. Ответ API для запроса с Origin `https://lampa.mx` разрешил этот origin. |
| Живой плейлист | Для сезона 1, серии 1 манифест после перенаправления содержал 480p, 720p и 1080p. Высоты получены из `RESOLUTION`. Дочерние плейлисты всех трёх вариантов открылись как медиа-плейлисты HLS. |
| Воспроизведение и интерфейс | В браузере Chromium на сборках Lampa 3.4.6 и 2.4.6 проверены ввод с экранной клавиатуры, выбор стрелками, смена серии на границе сезонов, возврат из плеера и восстановление настроек. Тестовые видео воспроизвелись в HLS 480p и 1080p и в MP4. В Lampa 3.4.6 дополнительно проверены ввод и мышь в режиме ноутбука и открытие одиночного видео на тестовом каталоге. |
| Код плагина | `npm test` запускает сборку и девять тестов каталога, выбора качества, относительных ссылок, MP4, ошибок манифеста, отмены запроса и запасного режима XMLHttpRequest. Синтаксис готового скрипта проверен парсером ES5. |
| API Lampa | Интеграция сверена с исходным кодом Lampa 3.4.6. Пункт меню создаётся через `Menu.addButton` либо через разметку меню в старых сборках. Экран использует `Component.add`, `Activity.push`, `Controller`, `Input.edit` и `Select.show`. Запуск и возврат обрабатывают `Player.play` и `Player.callback`. |

Проверенные исходники Lampa — [меню](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/menu/menu.js), [контроллер](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/controller.js), [коды пульта](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/core/keypad.js), [экранная клавиатура](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/settings/input.js), [списки выбора](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/select.js) и [плеер](https://github.com/yumata/lampa-source/blob/86c2b099b19f7058ea304dfa43a8b1e18a2e0492/src/interaction/player.js). Проверенные сборки — [3.4.6](https://github.com/yumata/lampa/tree/6fcdfab624f98ac0f7a91244e3d3b637f104a8c2) и [2.4.6](https://github.com/yumata/lampa/tree/ee25575845374a31b42d6b599f632a107e4eba3b).

- Для полнометражных фильмов требуется подтверждённый `content-id`. Если каталог вернёт одиночное видео с `episodeVariants`, плагин его откроет. Отдельный маршрут источника для полнометражных фильмов пока не подтверждён.
- Доступ зависит от Origin, настроек и сетевого движка сборки Lampa. На движках без Fetch используется XMLHttpRequest. После редиректа для относительных ссылок нужен конечный URL ответа, который старые реализации XMLHttpRequest могут не отдавать.
- Выбор разрешения опирается на данные манифеста. Способность телевизора декодировать поток зависит от его плеера, кодеков и прошивки. Проверка на физических телевизорах ещё нужна.

### Чек-лист для настоящего телевизора

1. Установить HTTPS-скрипт, открыть боковое меню и дойти до **Видео по ID** пультом.
2. Ввести `144537` цифровой раскладкой Lampa. Проверить, что «Назад» закрывает ввод, оставляет введённый ID и возвращает фокус к полю. Затем загрузить список.
3. Стрелками открыть каждый список, подтвердить выбор и отдельно проверить возврат без выбора. Дойти до последней серии первого сезона и перейти к первой серии второго кнопкой **Следующая серия**. Проверить обратный переход.
4. На первой серии отдельно проверить 480p и 1080p. Оценить старт, звук, перемотку и возврат фокуса из плеера. Отдельно открыть сезон 2, серию 7 для MP4.
5. Выйти из плагина и перезапустить Lampa. Сверить сохранённые ID, серию и настройки. Повторить на каждом целевом старом телевизоре с его установленной сборкой Lampa.

## Исходники и сборка

| Путь | Назначение |
| --- | --- |
| `src/main.js` | Подключение к Lampa и пункт меню |
| `src/screen.js`, `src/view.js`, `src/style.css` | Состояние экрана, управление фокусом и интерфейс |
| `src/catalog.js`, `src/hls.js`, `src/transport.js` | Адаптер каталога, определение качества и сетевые запросы |
| `scripts/build.js`, `test/core.test.js` | Сборка без внешних пакетов и модульные тесты |
| `docs/lampa-content-id.js` | Готовый файл для HTTPS-хостинга |

Сборке нужен Node.js 18 или новее. Для использования в Lampa достаточно готового файла.

```bash
npm run build
npm test
```

Для будущего поиска экран уже принимает `contentId` и `contentTitle` через параметры активности. Отдельный адаптер поиска сможет выдавать эти поля и открывать существующий экран.

```js
Lampa.Activity.push({
    component: 'lampa_content_id',
    title: 'Видео по ID',
    url: '',
    page: 1,
    contentId: result.contentId,
    contentTitle: result.title
});
```

Адаптер поиска должен получать именно ID видеоплеера. В проверенном примере ID карточки сайта `17335060` и `content-id` `144537` относятся к разным уровням. Сопоставление этих значений и поиск по названию относятся к следующему этапу.
